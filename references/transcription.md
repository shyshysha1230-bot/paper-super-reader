# 转录规则（PDF → Markdown，Stage 00）

本规则只在**启用转录**时适用；默认精读可直接读取 PDF，无需转录。转录的作用是把 PDF 变成可检索、可复跑、可保留页码锚点的 Markdown，**不改变论文内容，也不产生分析**。

## 何时转录

- 用户显式要求（如“先转录这篇论文”），或阅读模式为 `transcribe`。
- 需要稳定复跑同一篇论文、或在纯文本环境下阅读扫描/多栏 PDF 时，建议先转录。
- 已有转录文件时**直接复用**，不重复转录。

## 工具

- 首选 **MinerU**。可使用宿主已配置的 MinerU 能力，例如：
  - MinerU Cloud API（需要 token，如环境变量 `MINERU_API_TOKEN`）；或
  - 宿主提供的 MinerU 脚本 / CLI（本地 mineru CLI 已不再首选）。
- 不硬编码个人路径与密钥；token 由宿主环境提供，**不得写入本 Skill、日志或输出报告**。
- 若宿主无 MinerU 能力，跳过转录，直接读取 PDF；**不得因无法转录而拒绝阅读或降低阅读质量**。

## 输出与命名

- 转录正文默认命名为 `00-原文转录.md`，与阅读报告放在**同一论文目录**。
- 若 MinerU 同时产出图片目录（如 `images/`），保留其默认命名，不改名为 `assets/`；报告中的图表引用保持指向实际文件。
- 与原 PDF 并存：原 PDF 是底稿，**不移动、不复制、不删除、不改名**。

## 读取来源优先级

1. 优先读取 `00-原文转录.md` 进行阅读与分析。
2. 当转录文本缺失、乱码、公式/表格明显失真或与图表不符时，**回看原 PDF 核对**。
3. 引用来源锚点时，**页码以原 PDF 为准**（转录的页序可能与原 PDF 不完全一致）。

## 纪律

- 转录只做“文本化”，不混入总结、评价或改写。
- 不删除转录中的图表标题、公式、单位与作者原文措辞。
- 覆盖策略见 SKILL 的落盘规则：已有转录文件时复用，不静默覆盖；需重做时按“覆盖策略”处理。
